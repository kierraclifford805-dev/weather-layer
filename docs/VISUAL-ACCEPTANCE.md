## 后续：突出昼夜温差

按用户新增要求，将原先小时趋势下方的温差小提示提升为首屏暖黄色提醒。沿用 **最高与最低气温相差至少 10°C** 的门槛；高低温缺失／无效时不触发，不用体感值替代气温相减。早间 07–09 时、晚间 18–21 时的最低体感独立标明；缺失的时段不编造。温差与“比前一日降温”不再互斥。

新增 `shared/temperature-alert.js`，首页和穿衣简报共用；简报预览、详情及未来服务端组装的通知文本均包含提醒。没有改动原穿衣阈值、推送排程或开启状态，没有发送真实推送。

- 自动化全量 **111 项通过**（此前 104 项加 7 项回归）；覆盖 9.99 / 10°C 边界、零值、无效和溢出数值、跨年目标日期、缺失早晚数据、同时降温、日期切换和切换城市后的旧提醒清理。最后的数值溢出保护补验相关 20 项全部通过。
- 实际浏览器 **375px 浅／深色、1440px 深色** 均无横向溢出；切换至温差不足的明天后，旧提醒消失。
- 开发场景明确标注模拟数据：[375 浅色](images/visual-refresh/temperature-range-375.jpg)、[375 深色](images/visual-refresh/temperature-range-dark-375.jpg)、[1440](images/visual-refresh/temperature-range-1440.jpg)。示例 8–25°C／温差 17°C 仅用于开发排版验收。
- [真实 Open-Meteo 北京 2026-10-05 简报](images/visual-refresh/temperature-range-brief-real.jpg)成功显示：11.5–24.4°C，昼夜温差 12.9°C，早间最低体感 9°、晚间 16°。这是此次查询快照，预览未开启或发送通知。

## 视觉与功能变化

- 雾白、柔蓝、少量暖黄，独立深色主题。设计变量位于 `styles.css` 顶部；过渡为 220ms，天气窗入场后停止，支持 `prefers-reduced-motion`。
- 首屏先展示对应日期的出门结论，天气窗位于旁侧，温度、城市、日期作为支撑。今日实况与明日预报明确区分；改变主题不会改变日期或天气场景。
- 22 个自行绘制的本地 SVG：8 种天气、14 种衣物及随身物品。穿在身上与随身带着分开，保留衣物名称、用途、推荐原因和体感偏好。
- UV 为目标日期每日最大预报值，显示数值、原有三档等级、水平刻度、行动和 WHO 来源；缺失显示信息暂缺，不显示数值指针。
- 首页提醒收为「今晚准备单」。手机底部面板、桌面右侧面板，保留固定城市、时间、时区、目标日、模块和简报预览。
- 六个关键小时支持点击、方向键、Home / End，详情随选择更新；小时数据不足会独立降级。七天预报共用温度刻度，保留每天明确的最低／最高值。
- 首次进入、加载、无数据、部分缺失、请求失败均有明确状态。更新失败保留已有内容。修正了窄屏衣物标签断字、无数据文字被挤进一列、插画高度及桌面等高卡片多余留白。

## 功能边界与剩余配置

**真实可用**：城市搜索、Open-Meteo 天气、今天／明天、原有穿衣与体感偏好、UV、小时详情、七天预报、主题、本地准备单和真实天气简报预览。

**当前不提供定时发送**：`API_BASE` 仍为空。开启／测试通知不可用并解释原因；本地保存不申请权限、不上传订阅、不宣称定时提醒已开启，也不把计算出的预览时间说成服务端下一次真实任务。

真正上线仍需 Cloudflare 账号、D1 数据库与迁移、VAPID Secrets、Workers / Cron 部署、前端 API_BASE 与精确 CORS。详见 [部署和回退](DEPLOYMENT.md)。本轮未配置这些资源，未自动发布。

**未验证**：iPhone / iPad、Android、Safari、Firefox / Edge 真机；系统字体放大及屏幕阅读器；系统减少动态效果开关的设备实测；雪／雾／雷暴和所有极端温度插画的逐项人工实景检查。SVG 文件与映射已检查，不等于这些天气场景都在真机出现过。

通知权限拒绝、订阅失效、保存失败等通过自动化验证；真实系统授权、云端 Cron、关闭网页后的真实推送与通知点击仍需部署后逐设备验收，不能以模拟事件或服务端接受状态替代。
