## 自动化覆盖明细

- 日期：跨日、跨月、跨年、闰年、国际日期变更线；纽约夏令时缺失／重复时刻、Lord Howe 半小时跳时、尼泊尔非整点时差；下一次提醒按当地日历计算。
- 目标：周一出门在周日发送；单次目标已过前夜时间会拒绝；有效期不越过目标日零点；任务快照和重试中的日期固定。
- 规则：`daily.time` 查找指定日期，兼容额外历史日、非相邻日期和缺少 current；原有体感规则保持。
- UV：缺失、null、字符串、负数、NaN、Infinity；有效 0；2.999 / 3 / 7.999 / 8 边界；仅使用 uv_index_max。
- 模块降级：穿衣无数据时保留 UV；UV 失败时保留穿衣；两路日期顺序不同仍按日期合并；UV 响应结构损坏不会抹掉有效穿衣数据。
- 排程：并发领取、重叠 Cron、租约恢复与旧持有者隔离、改时间／城市使旧任务失效、发送前关闭、三次有限重试、Retry-After 超过 TTL、超时结果未知、发送中断、过期不补发、单次计划完成。
- 推送协议：真实调用维护库构建 AES128GCM 密文；使用独立 `http_ece` 实现成功解密；使用 Node 标准签名验证校验 VAPID JWT、audience、TTL、Topic 和过期阻断。未连接真实推送供应商。
- Service Worker：在没有页面对象的测试上下文中处理 push；并发重复事件只展示一次；关闭、旧版本、过期消息丢弃；点击携带原城市／目标日，拒绝跨站／越出 `/weather-layer/` 的地址。IndexedDB 为测试实现，通知展示为模拟。
- 安全：缺少凭证、猜测 ID、另一个 capability 不能操作他人订阅；不可抢占已绑定 endpoint；严格 CORS；8 KiB 上限；无效 IANA / 时间 / 城市 / 未实现模块拒绝；危险推送域、协议与端口拒绝；P-256 公钥和订阅到期校验；测试限流；级联删除。
- 前端：仅主动保存申请权限；拒绝权限不注册；浏览器不支持时保留预览；未配置不误报；临时城市／体感变化不污染提醒设置；七天预报保留；通知详情锁定目标日期。
- 表单与接口串联：开启 → 测试排队 → 修改 → 关闭 → 重新开启 → 删除服务端数据。

实际 workerd 测试曾发现 D1 的 LIKE 模式长度限制，导致按 64 位哈希前缀清理限流记录失败；已改为索引范围查询，并在同一运行时验证删除成功。这个问题没有用 SQLite 测试结果掩盖。

## 部署后的真实设备验收步骤

先按 [部署说明](DEPLOYMENT.md) 配置 Cloudflare 账号、D1 数据库和迁移、VAPID 三项 Secrets、Worker origin、前端 API_BASE 与精确 CORS；确认 HTTPS 下的 manifest、SW、图标路径均在 `/weather-layer/`。

1. 在每种目标浏览器打开网站。iPhone / iPad 先添加到主屏幕。第一次拒绝授权，确认未开启且原有天气可用；随后在系统设置允许再开启。
2. 固定一个与设备时区不同的提醒城市，设一个几分钟后的当地时间。核对页面下一次 UTC 对应的当地日期、时间、目标出门日。
3. 点击测试通知并**关闭所有该站网页窗口**。等待真实系统通知；记录设备型号、系统／浏览器版本、收到时间、服务端任务 ID。未收到就记失败／待排查，不能凭 push_accepted 判通过。
4. 点击系统通知，检查城市、时区、目标出门日期和详情；保存一份状态截图。不要截取订阅地址、管理凭证和私钥。
5. 在周日验证周一简报；或在隔离测试环境使用可控日期验证调度，再在真实周日复验。勿通过更改生产服务器时间制造通过记录。
6. 修改时间和提醒城市，确认旧任务取消、新计划正确；关闭提醒后检查待执行任务失效、本地取消订阅；删除后回读 D1 无本设备订阅、计划与记录。
7. 让设备离线越过 TTL，再联网，确认没有过期通知；收集生产供应商失效响应时确认停用。重试／并发／故障注入仅在隔离测试环境进行。

建议验收记录列：设备、系统、浏览器版本、主屏幕模式、通知授权、计划当地时间、目标日、服务端状态、实际收到时间、点击结果、结论。只有设备实际接收后才标记该设备的端到端通知通过。
