# 添一件：穿衣档案与合身推荐

2026-10-25。在原有静态项目上迭代，未新增框架、npm 依赖、推送服务或图像识别服务；未提交、推送或发布。原有大量未提交修改保留。

## 用户流程与真实能力

1. 每日穿搭中点「去完善」，或在「我的衣橱」中点「编辑档案」。可选填身高、体重、胸围、腰围、臀围及合身／宽松偏好；单位为 cm／kg。
2. 在已有衣物点「尺码／编辑」，直接展开尺码信息，不必重新导入照片。填写原尺码标签、实际穿着感受，必要时补充来自品牌尺码表或已确认试穿结果的适用身体范围。
3. 每日推荐先沿用既有天气规则，再优先选取舒适、符合偏好与已填身体范围的单品。偏紧或超出范围的衣物暂不自动推荐；未知尺码保留并明确标注。
4. 可单件替换并记住这套。身体档案变动后，旧搭配需重新确认；保存档案后返回原界面，重新打开面板回到顶部，草稿不会自动保存。
5. 衣橱支持隐藏已知不合适的单品，与名称、类型和厚薄筛选组合；未知尺码继续展示。可清除身体档案，并在本页再次保存或关闭之前撤销清除。

这是基于明确填写信息的衣物筛选与排序。身高体重不会被换算成三围、体型或通用 S/M/L；没有衣物范围时不能仅凭身体数据得出尺码结论。适用身体范围不是衣物平铺尺寸。具体品牌仍需结合品牌表与试穿确认；参考 [UNIQLO 测量说明](https://faq-eu.uniqlo.com/articles/en_US/Knowledge/How-can-I-find-out-what-measurements-UNIQLO-sizes-are-EU)。未使用模型自动识图、身体分析或虚拟试衣。

执行 `node --test tests/*.test.js`：**191 passed，0 failed**（新增 24 项）。同时通过相关 JS 的 `node --check` 和 `git diff --check`。

新增检查覆盖：

- 所有身体字段选填；无效数值、单位范围与错误格式不写入；不从身高体重推算缺失数据。
- 档案读写键独立，未变动保留版本，实际变动更新版本；损坏记录、未知版本及存储拒绝不会假报成功或静默覆盖。
- 身体范围端点包含在内；单边界有效；部分身体数据缺失显示尚未核对；上下装只参考相关围度，随身物品不按身体尺码筛选。
- 舒适与偏好排序；偏紧／超范围不自动选择；仍不能用薄衣替代天气要求的厚衣。
- 旧衣物无需新字段即可使用；照片与新增尺码对象保留；无效尺码不破坏已有记录。
- 新旧备份读取、尺码往返、指纹和冲突合并、恢复预览过时检测；身体档案不写入衣物备份。
- 档案保存前不应用，关闭／重开丢弃草稿并回到顶部；保存不重新请求天气或更改天气偏好。
- 衣物范围实际改变推荐、筛选与备份范围；解释对应输入；错误范围保留编辑草稿。
- 档案清除与撤销；写入失败保留旧值；损坏档案时天气仍工作。
- 从衣橱打开子档案，关闭／返回保留父弹层与焦点；旧页面草稿不能覆盖另一页面刚更新的档案。
- 身体资料变动使已记住搭配需要确认，搭配记录仅含随机档案版本，不复制身体数值。

## 数据、迁移与回退

- 新键 `weather-layer-body-profile-v1` 存可选身体数值、偏好和随机版本；保存后才写入。不发送给 Open-Meteo、Cloudflare 或其他服务，也不导出进衣物备份或推送。
- 衣物的尺码标签、穿着感受、适用身体范围是衣物记录的一部分，会随衣物备份导出。备份含照片及这些资料，未加密，请自行保管。身体档案与衣物范围的含义在表单、隐私说明及 README 中有区分。
- 清除身体档案不删除照片。撤销清除的临时副本仅保留在当前页面内存；再次保存或关闭页面后不能再撤销。
- IndexedDB 沿用原版本与记录，不重置照片。旧备份兼容，新字段为可选；旧版本程序可能忽略新尺码字段，迁移请使用本次版本。
- 没有新增账号、密钥或接口配置。推送后端仍未配置，设置／简报可预览，不能当作真实提醒已开启。
- 需要回退时，仅还原本轮文件；编辑前快照 `/tmp/weather-layer-before-fit-20261025/`。不要对全仓库使用 reset／checkout，避免覆盖此前未提交工作。新档案键可保留不用；原衣橱照片仍有效。

未验证：真实人体穿着效果、品牌尺码表自动导入、手机真机与系统软键盘、Safari／VoiceOver／TalkBack、真实存储配额耗尽，以及云端／真实设备推送。本轮照片选择器和系统下载器未重复验收；对应备份数据变化已由自动测试覆盖。
