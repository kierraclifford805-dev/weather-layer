# 添一件 · 每日穿衣天气

一个无需前端构建的静态天气工具。保留 GitHub Pages；可选的「明日出门提醒」使用独立 Cloudflare Workers + D1 + 每分钟 Cron + Web Push。

[打开添一件](https://kierraclifford805-dev.github.io/weather-layer/)。前端使用 GitHub Pages，明日提醒服务需要独立配置与部署。

## 日常天气

- 城市／区县搜索、当前天气、七天预报、早晚体感。
- 沿用「怕热／刚刚好／怕冷」和 07:00–21:00 最低体感穿衣规则。
- 打开页面刷新；页面在前台时每 30 分钟检查更新及当地日期变化。
- 原有 `weather-layer-v1` 本地偏好保持兼容。

## 界面与交互

- 首屏以真实日期对应的出门建议为主，配本地 SVG「天气窗」；今天／明天切换天气日期，浅色／深色仅切换外观。
- 衣物平铺分为「穿在身上」与「随身带着」。沿用原有穿衣阈值，素材映射集中在 `visuals.js`。
- 「今日／明日穿搭推荐」可查看全天、早间、白天、晚间；所选时段使用当地可用小时预报的最低体感，仍调用原有穿衣规则。全天默认保持 07–21 时，随身准备与温差仍参考整天预报。
- 所选日期的最高／最低气温相差 **至少 10°C** 时，首屏突出「昼夜温差」提醒，并加入穿衣简报。早晚最低体感仅使用已有分时预报；缺失则省略，不把全天温差冒充两个具体时刻的温差。判断集中在 `shared/temperature-alert.js`，与降温提示独立。
- 防晒显示所选日期的最高 UV 预报、三档行动建议与水平刻度；缺失不补零，不虚构小时曲线。
- 小时详情支持点击、方向键、Home / End；七天温度区间共用同一刻度。刷新失败保留已加载内容。
- 手机单列、桌面有主次的双栏；提醒详情为手机底部面板／桌面侧边面板，支持 Escape、返回、焦点归位和背景滚动锁定。
- 颜色、字号、间距、圆角和过渡集中在 `styles.css`。主题单独保存到 `weather-layer-theme-v1`；支持减少动态效果的系统偏好。

改造前后与关键状态截图、四种宽度的实际检查见 [界面验收报告](docs/VISUAL-ACCEPTANCE.md)。

## 我的衣橱（本机版）

在穿搭区点击「我的衣橱」，或首次进入时点击「先整理我的衣橱」。

- 导入自己的照片，逐件确认名称、衣物类型和厚薄；支持编辑、移除、恢复和确认后的永久删除。
- 一次最多 12 张、每张不超过 12 MB；支持 JPG、PNG、WebP、AVIF，HEIC 需先转 JPG。照片在浏览器内缩至最长边 960px、重编码为 JPEG 后保存，避免保存原图定位等 EXIF 信息。
- IndexedDB 最多保存 100 件在用衣物。照片与分类只保存在当前网站、当前设备的浏览器，不发送到天气接口或提醒后端，不跨设备同步。清理网站数据、切换域名或浏览器可能失去衣橱，请保留原照片。
- 根据原有天气规则、体感偏好、所选日期和时段，优先匹配衣橱中类型与厚薄合适的单品；展示实际照片与名称。没有合适衣物时仍给出插画建议，明确标注「建议单品 · 衣橱暂缺」，不会拿厚外套冒充薄外套。
- 同一日期、时段的推荐保持稳定；有合适的同类备选时可「换一套」。支持的首版分类为短袖、长袖、针织衫／卫衣、保暖内搭、薄外套、常规外套、厚外套、羽绒服、长裤、轻薄下装，以及帽子、雨伞、防晒霜、水杯。
- 有合适备选时，每件衣物下方提供「换这件」：查看真实衣物照片、名称和厚薄，只替换当前这一件；随身物品同样支持。不会显示不符合原有规则的单品。
- 挑好后点「就穿这套 · 记住」，按城市坐标＋IANA 时区、当地日期、全天／早间／白天／晚间分别保存在本机；最多保留最近 30 组。更换单品只是预览，明确确认后才保存。支持回到记住的搭配、恢复自动推荐和取消记住。
- 再次打开时会核对天气建议、个人体感偏好和衣橱。建议变化、衣物移除或分类厚薄不再匹配时，展示当前规则下的推荐并提示重新确认，不把旧搭配当成有效结论。
- 这是根据手动分类的天气搭配，不包含 AI 识图、自动抠图、色彩／场合造型分析。衣橱搭配目前用于网页；明日提醒仍使用通用天气穿衣建议，不读取或上传本机衣橱。
- 格式不支持、解码失败、存储空间不足或保存失败会明确提示；没有有效体感数据时不生成自有衣物穿搭。天气请求失败仍可打开衣橱管理。
- 「查找与筛选」可组合名称／类型关键词、上衣／外套／下装／随身物品分类和厚薄，也可筛选最近移除。手机默认收起筛选，先展示衣物；筛选结果数量与清除入口始终可见。
- 「这套怎么选的？」说明目标日期、时段最低体感、个人体感偏好与各件衣物的匹配标注，缺少匹配单品也会解释原因。
- 「备份与迁移衣橱」可下载含照片的 JSON 文件，仅包含当前筛选的**在用衣物**（不含最近移除）。清除筛选后可备份全部；每份最多 64 MB，较大衣橱可按分类分批备份。
- 从备份恢复先在本机校验照片并展示逐件合并计划，确认后才写入。相同衣物跳过，编号冲突且内容不同的衣物作为新副本加入；相同的已移除衣物会重新启用。已有衣物保持不变，重复恢复不会不断添加副本。
- 恢复采用单次 IndexedDB 事务；超限或中断时不写入半份。其他标签页更新衣橱后，旧恢复预览需点击「重新检查」再确认。

## 穿衣档案与合身筛选

在每日穿搭中点击「去完善」，或在衣橱中点「编辑档案」。可选填身高（cm）、体重（kg）、胸围／腰围／臀围（cm），以及合身／宽松偏好。先填常用资料也可以，保存后才应用；未保存修改可撤销，关闭后重开会读取上次保存值。

- 在衣物卡片点「尺码／编辑」，直接展开合身信息。可填写原尺码标签（例如 M）、实际穿着感受，以及来自该件品牌尺码表或已确认试穿结果的**适用身体范围**。范围下限／上限可单独填写；这里不是衣物平铺尺寸。
- 身高、体重与衣物范围直接对照；上衣额外参考胸围，下装参考腰围、臀围。范围端点包含在内；有一项已填身体数据超出对应范围时，自动推荐会暂时跳过这件衣物。标记「偏紧／活动受限」的衣物也会跳过。
- 沿用天气温度阈值，先筛天气合适的单品，再优先选择已确认舒适、符合穿着偏好及身体范围的衣物。随身物品不按身体尺码筛选。
- 没有对应的衣物范围时，填身高体重也不会凭空算出尺码。旧衣物继续可用，明确标「尺码待确认」；缺少的围度不会从身高体重推算。系统不进行 BMI、体型或健康评判。
- 身体档案变化后，已记住的搭配需要重新确认；搭配记录仅增加随机档案版本标识，不复制身高、体重或围度。
- 衣橱可「隐藏已知不合适的衣物」，未知尺码仍保留。此筛选与搜索／分类／厚薄组合，备份范围按实际筛选结果计算。
- 身体档案独立保存在本机 `weather-layer-body-profile-v1`，不上传、不进入衣橱备份或推送；可清除，当前页面再次保存或关闭前可撤销清除。衣物的尺码标签、适用范围和穿着感受会随**衣物备份**保存，不包含独立身体档案。
- 这里只提供已有衣物的天气与合身参考；具体品牌尺码仍需结合品牌表和试穿确认。[UNIQLO 的测量说明](https://faq-eu.uniqlo.com/articles/en_US/Knowledge/How-can-I-find-out-what-measurements-UNIQLO-sizes-are-EU)建议用实测身体或现有衣物与具体商品的尺码表对照。

本轮截图、文件变化、191 项测试及未验证范围见 [身体资料与合身推荐验收](docs/BODY-FIT-2026-10-25.md)。

## 明日出门提醒

面板提供：开启／关闭、当地提醒时间、**独立固定城市**、IANA 时区、每天／仅工作日／自选星期／单个日期、穿衣与防晒模块、提醒专用体感偏好、预览、服务端测试推送和删除数据。

- 简报目标是发送日期的下一个当地日历日。「仅工作日」筛选目标出门日，周一简报在周日发送；不识别法定节假日或调休。
- 保存后显示服务端下一次提醒的日期、时间、时区及目标日期。未保存修改与已保存计划分开显示。
- 刷新状态、重新打开页面会保留未保存的有效设置草稿；修改设置立即清除旧预览，避免把旧城市或日期的结果当成新预览。
- 断网关闭／删除会保留待处理操作，独立尝试本地退订和服务端清理，联网或重新打开后重试；完成前明确显示待确认，并暂停重新开启与测试。
- 修改时间、提醒城市、时区或内容会创建新版本，使旧待发送任务失效；临时查城市不会改变提醒城市。
- 明日计算不依赖当前气温。`daily.time` 匹配日期，兼容 `past_days=1`。穿衣和防晒独立请求、独立降级。
- 紫外线使用 Open-Meteo **`daily.uv_index_max`**；标明「明日最高紫外线指数，预报值」。不使用晴空值，不从晴阴或温度推测。
- 防护分为 `<3` 日常关注、`3 至 <8` 需要防护、`>=8` 加强防护，依据 [WHO 紫外线指数指引](https://www.who.int/news-room/questions-and-answers/item/radiation-the-ultraviolet-%28uv%29-index)。缺失／无效数据为「信息暂缺」，有效 `0` 原样保留。没有精确高峰时段或安全暴晒时长推断。
- 网页关闭后由服务器执行排程，Service Worker 处理推送及点击；通知深链接固定城市、日期和时区。
- iPhone / iPad 需 iOS / iPadOS 16.4+，添加到主屏幕后开启通知。权限只在用户勾选开启并保存时申请。[WebKit 说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

**默认 `reminder-config.js` 的 `API_BASE` 为空，定时提醒未开启。** 此时原有天气、提醒设置草稿和预览仍可使用。不能把本地通过测试或“推送服务已接受”当作已在真实设备收到通知。

后端未配置或不可用时，「保存本地准备单」只保存本机草稿，页面明确标注计算出的时间为预览；开启和测试通知按钮不可用，并说明原因。已有服务端计划仍保留关闭／删除与恢复入口。

## 数据与隐私

未开启提醒时，查询城市、体感、界面主题、提醒设置草稿只保存在当前浏览器。天气和城市搜索会把所选坐标、时区或搜索词发送给 [Open-Meteo](https://open-meteo.com/)。不自动获取精确设备位置。

衣橱照片、名称、分类、厚薄以及可选尺码／穿着感受／适用身体范围单独保存在本机 IndexedDB（`weather-layer-closet-v1`）。界面以本机 Blob 地址显示照片，不上传到 Cloudflare、Open-Meteo 或其他图像服务。移除的衣物仍占用本机空间且可恢复；在「最近移除」中确认永久删除后移除照片记录。浏览器可能回收网站存储，原照片需要自行保留。

明确点击「记住」后，搭配的城市坐标、时区、日期、时段、规则标识及衣物编号保存在独立 localStorage 键 `weather-layer-outfits-v1`，不复制照片或上传到服务端。最多保留最近 30 组；每组可在对应日期／时段取消记住。此记录不进入衣橱备份，不参与明日推送；清除网站数据后会丢失。

身体档案在点击保存后才写入独立 `weather-layer-body-profile-v1` 本机键，包含自填的身体数据与偏好，不发送给天气或提醒服务，不包含在衣物备份中。首页仅显示已填写项目数量，具体数值在档案中查看。

下载的衣橱备份包含照片、分类和衣物尺码／适用身体范围／穿着感受，未加密，请自行保管。备份不包含天气城市、体感偏好、提醒计划或提醒管理凭证；恢复衣橱不会更改这些设置。导出与恢复均在本机进行，文件迁移需由用户自己完成，不等于云同步。

开启提醒后，固定城市坐标、时区、时间、出门日、模块选择、提醒体感和浏览器推送订阅（地址、订阅公钥）上传到独立 Cloudflare 服务。随机 256 位管理凭证只保存在浏览器，服务端存其 SHA-256 哈希，所有管理、测试、删除操作须携带此凭证。不要共享凭证或将它放到 URL、日志、GitHub。

D1 保存计划、任务和发送记录。记录保留 30 天；180 天未注册更新的设备数据自动清理；短期限流保存 IP 哈希与计数，应用不记录完整推送地址和密钥。浏览器厂商的推送服务负责传递加密消息。

「关闭提醒」停排程、使待发送任务失效并取消本地订阅，保留设置；「删除服务端数据」级联删除订阅、计划、任务和记录。服务不可达时会在本地保存关闭／删除意图并保留管理凭证供重试，不宣称已删除。删除请求即使已完成、但浏览器没收到响应，也可安全重试。清浏览器数据前请先确认操作完成，否则管理凭证将丢失。已交给推送服务的消息无法撤回，设备端尽力过滤关闭、旧版或过期消息。

## 扩展边界与来源

数据源、规则模块、简报组装与发送渠道已分离。首版只实现 `clothing`、`sun` 和 `webPush`；`rain`、`airQuality` 和邮件尚未实现，接口拒绝未注册模块，不展示假开关。

- [Open-Meteo 预报字段与时区](https://open-meteo.com/en/docs)、[城市搜索](https://open-meteo.com/en/docs/geocoding-api)、[服务条款](https://open-meteo.com/en/terms)。默认公共接口适用于个人非商业使用，上线运营时核对配额与授权。
- [Cloudflare D1 批事务](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/)。
- [Web Push 实现](https://github.com/block65/webcrypto-web-push)：使用已发布 `@block65/webcrypto-web-push@2.0.0`，AES128GCM / VAPID 交由库实现；本项目没有自写加密算法。
